# ADR-001: Lenguaje de Bootstrap del Compilador Zen

**Fecha**: 2026-11-10
**Estado**: ACEPTADA
**Autor**: Agente 00 (Orquestador) con input Agentes 01, 02, 03
**Tarea relacionada**: TASK-008

## Contexto

Necesitamos implementar el compilador Zen v0 (Fases 1-3: frontend, typechecker, backend codegen) antes de que Zen pueda compilarse a sí mismo. El lenguaje anfitrión debe:
- Estar disponible en el entorno actual
- Tener bindings maduros a LLVM para codegen optimizado
- Permitir desarrollo seguro y mantenible
- Facilitar transición futura a self-hosting

## Decisión

**Implementar el compilador Zen v0 en Rust 1.99+ usando `inkwell` (Rust bindings para LLVM C API) como backend de generación de código.**

## Justificación Detallada

### ✅ Rust + inkwell (ELEGIDO)

| Criterio | Evaluación |
|----------|------------|
| Disponibilidad | ✅ Ya instalado (rustc 1.99.1, cargo 1.99.1) |
| LLVM bindings | ✅ `inkwell` maduro, seguro, API tipada sobre LLVM C API |
| Codegen quality | ✅ LLVM completo: optimizaciones, LTO, SIMD, multi-target |
| Memory safety | ✅ Rust evita bugs de memoria en el propio compilador |
| Ecosistema | ✅ Excelente: `clap` (CLI), `lalrpop`/`pest` (parsing), `codespan` (diagnostics) |
| Self-hosting path | ✅ Zen → compila Rust → compila Zen (vía LLVM IR o backend nativo) |
| Team familiarity | ✅ Conocido, documentado, buen tooling (rust-analyzer) |
| Build system | ✅ Cargo: reproducible, parallel, test integration |

### ❌ Alternativas Rechazadas

| Opción | Razones |
|--------|---------|
| **C++ + LLVM API nativa** | Verboso, manual memory management, mayor surface para bugs, build system complejo (CMake), slower iteration |
| **Cranelift (Rust)** | Codegen menos optimizado, menos targets, menos maduro para optimizaciones agresivas (PGO, LTO, vectorización avanzada) |
| **Backend propio (desde cero)** | Coste enorme (años), reinventar optimizaciones LLVM, posponer a Fase 8+ solo si justificado por mediciones |
| **Zig** | No instalado, añade dependencia externa, similar a Rust pero ecosistema LLVM menos maduro (`zig cc` bueno pero `inkwell` equivalente menos desarrollado) |
| **Go / OCaml / Haskell** | LLVM bindings menos mantenidos, GC complica freestanding, menos 익숙 |

## Plan de Migración a Self-Hosting (Fase 9)

1. **Fase 1-3**: Compilador Zen en Rust + inkwell → genera ejecutables nativos
2. **Fase 3+**: Zen gana capacidades freestanding (no_std, raw pointers, inline asm, custom sections)
3. **Fase 9**: Reescribir frontend (lexer, parser, AST, typechecker) en Zen
4. **Fase 9**: Backend: opción A — emitir LLVM IR desde Zen + compilar con `llc`/`clang`; opción B — backend nativo Zen (Cranelift o propio) si benchmarks justifican
5. **Verificación**: Compilador Zen-en-Zen compila compilador Zen-en-Zen → bitwise identical output (reproducibilidad)

## Riesgos y Mitigación

| Riesgo | Impacto | Mitigación |
|--------|---------|------------|
| inkwell version lag vs LLVM | Medio | Pin LLVM version en Cargo.toml; testear upgrades en rama separada |
| inkwell API incompleta | Bajo | LLVM C API completo accesible via `inkwell::llvm_sys` si necesario |
| Compile times Rust | Bajo | Cargo incremental, `cargo check` rápido, mold linker |
| Self-hosting complexity | Alto | No bloquear kernel en ello; Fases 1-8 usan compilador Rust |
