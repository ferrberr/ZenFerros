# ADR-009: Primer boot con Multiboot1, payload Zen x86_64 y QEMU TCG

**Fecha**: 2026-11-11
**Estado**: ACEPTADA
**Responsable**: 00 Orquestador, revisión TASK-411
**Dependencias**: ADR-008, TASK-310

## Problema y alternativas

Falta demostrar que código máquina generado desde Zen se ejecuta en ring 0, fuera del proceso Linux de Hito 2. El entorno tiene GCC/binutils pero no QEMU, KVM, GRUB, xorriso ni Limine instalados. Limine sigue siendo candidato para futura imagen BIOS/UEFI; integrarlo ahora exige componentes adicionales de firmware/imagen. QEMU ofrece carga directa Multiboot1, suficiente para un primer hito verificable sin discos físicos ni ISO.

## Decisión

Compilar kernel Zen a objeto ELF64 freestanding. Bootstrap asm original implementa header Multiboot1 y entrada32, BSS, GDT, tablas de páginas y transición long-mode64. Enlazar a 1 MiB con ld elf_x86_64 y max-page-size 4096. Convertir el ELF enlazado mediante objcopy -O elf32-i386 a contenedor que acepta el loader Multiboot de QEMU; .text/.rodata se comparan byte a byte antes y después. No se transforma código64 a32: ELF32 es contenedor del cargador. Los helpers asm solo ofrecen in8/out8/out32/halt; UART/configuración/loopback/polling/mensajes/estado están en Zen.

Ejecutar QEMU TCG pc/qemu64, 1 vCPU, 64 MiB, sin red, discos ni interfaz gráfica, sin monitor, con puerto serie stdout y isa-debug-exit en0xf4. No se requiere /dev/kvm. El test exige salida exacta, stderr vacío y estado33 (valor guest0x10); fallo guest0x11 corresponde35. Timeout por proceso/grupo con terminación/recolección y logs, incluyendo Ctrl+C. No usar -no-shutdown: en QEMU11 isa-debug-exit solicita shutdown con código, y esa opción impediría que el proceso termine.

## Bootstrap y límites

La identidad inicial cubre [0,1GiB) con páginas2MiB, supervisor RWX. CR4 se fija a PAE, CR3 apunta a PML4, EFER.LME y CR0.PG/PE/WP se activan, GDT64 por salto lejano; stack64KiB alineado16 antes de call. Se preservan magic EAX e info EBX y se pasan como RDI/RSI zeroextend. Interrupciones deshabilitadas. Esto no es VMM con permisos, ni PMM ni IDT: Hito4 debe reemplazar el mapa bootstrap y gestionar excepciones.

La ABI externa para instrucciones privilegiadas es una excepción asm necesaria porque Zen todavía no tiene inline asm. No se ha incorporado un kernel en C ni un bootloader externo copiado. QEMU/SeaBIOS son herramientas externas GPL/LGPL/BSD y otras licencias según paquetes; no se enlazan al kernel. Versiones, URL y SHA256 se fijan en infrastructure/toolchains/qemu-packages.json y se extraen solo a .tools/qemu. Los archivos originales de licencias se conservan allí. No se cambian paquetes del anfitrión.

## Evidencia y condiciones de revisión

TASK-410/TASK-411: boots normales y optimizados, ELF/header/checksum/segmentos/símbolos, pruebas de UART con IO simulado y negativos de runner. No se declara soporte USB/ISO/UEFI, KVM, otros equipos ni drivers completos. Reconsiderar protocolo/layout cuando se necesiten mapa físico, framebuffer, higher-half o firmware UEFI.
