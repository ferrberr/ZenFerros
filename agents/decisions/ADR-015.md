# ADR-015: Mantener `-O2` en el backend C11 tras medir `-O3`/LTO

**Estado**: aceptada (2026-11-11)
**Contexto**: Fase 8 / TASK-802. `native.rs` compila el C generado con `cc -O2` en release.

## Problema
¿Mejora el rendimiento cambiar los flags de release (`-O3`, `-flto`)?

## Evidencia
`benchmarks/scripts/flags.py` generó C con `zen build --emit c --release` y compiló el mismo C con `-O2`, `-O3`, `-O2 -flto` y `-O3 -flto`. Checksums idénticos; 7 reps + 2 warmup, dos pasadas, CPU-time intercalado y CPU fijada. Resultados completos en `benchmarks/results/opt-flags.md`.

- Ninguna variante supera el umbral preregistrado (mejora >3 % en **todas** las cargas y ambas pasadas, sin regresión).
- `-O3` solo mejora de forma reproducible `collatz` (3,10/3,76 % en las dos pasadas) y `mem` queda en ±0,6 % (el 1,6 % de empeoramiento es de O3-LTO en la pasada 2).
- LTO aporta como máximo mejoras dentro del ruido y reduce el binario ~0,2 %; la compilación pasa de 0,04–0,05 s a 0,06–0,08 s (45,7–63,1 % más lenta).

## Decisión
Mantener `-O2`. No se cambia `native.rs`.

## Consecuencias
- Sin riesgo nuevo de LTO/tiempos de compilación.
- La decisión se revisará si aparecen cargas representativas donde la mejora sea consistente o si se incorpora un backend propio.
- No se declara superioridad de Zen: mide flags de GCC sobre el C generado, no un backend de Zen.
