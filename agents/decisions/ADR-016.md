# ADR-016: Arrays de tamaño fijo en el subconjunto MVP

**Estado**: aceptada (2026-11-11)
**Contexto**: TASK-213 (Hito 9). El autohosting necesita representar secuencias (tokens, AST); hasta ahora Zen solo tenía escalares, punteros raw y `str` literal.

## Decisiones

1. **Tipo `[T; N]` con `N` literal sin sufijo y `T` escalar** (`u8/u16/u32/i32/i64/u64/bool`). Sin arrays de arrays ni de punteros en esta etapa.
2. **Anotación explícita obligatoria** (`let mut a: [u64; 4] = ...`). No se infiere el tipo desde el literal: la inferencia de arrays exige un sistema de unificación que el MVP no tiene y haría ambiguos `[]`/`[e; N]`.
3. **Solo variables locales**. Parámetros, retornos, argumentos, copia, comparación, asignación completa, cast, slice, `.len`, multidimensionales y puntero a array se rechazan con diagnóstico localizado. Pasar arrays exige decidir semántica de copia/préstamo, fuera de alcance.
4. **Comprobación de rango en ejecución** con `__zen_index_check(idx,len)` antes de cada acceso: `__zen_fail` (stderr + exit 1) en hosted y `ud2` en freestanding, sin comportamiento indefinido. El índice se evalúa una vez y antes de la comprobación.
5. **`[e; N]` evalúa `e` una sola vez** y copia el valor N veces; el literal `[e1,...]` exige longitud exacta y tipos exactos.
6. **Sin `.len`**: la longitud está en el tipo; añadir un operador de longitud requiere semántica de tipos y no es necesario para el kernel ni para el primer AST.

## Alternativas rechazadas
- Arrays dinámicos/`Vec` en stdlib: no hay stdlib ni allocator del lenguaje; el heap del kernel es arena.
- Inferencia de arrays: ambigüedad y coste de unificación.
- Bounds check solo en debug: rompería la semántica idéntica debug/release y la seguridad del kernel.

## Consecuencias
- `zen run zen/examples/arrays.zen` y 9 tests de CLI (positivos, negativos y OOB) verifican la función; 57 tests de compilador en total.
- Los arrays son **locales y de tamaño constante**, suficientes para buffers del kernel y para tokenizar/representar un AST acotado, pero no para APIs generales.
- Condición de revisión: si se añaden structs o paso de arrays, revisar la semántica de copia y ampliar diagnósticos/tests.
