# ADR-012: ELF estático Zen en CPL3 y ABI int0x80

**Fecha**: 2026-11-11
**Estado**: ACEPTADA para el mínimo del Hito6; evidencia TASK-710 y revisión TASK-711.

## Decisión y alcance

Un programa de usuario activo cada vez, ejecutado después de terminar los threads del Hito5. El kernel conserva su mapa supervisor y añade una ventana virtual de2MiB en0x40000000. No hay scheduler de procesos ni CR3 distinto por tarea. Es aislamiento de páginas/privilegios y una ABI GPR mínima, no un entorno para binarios arbitrarios hostiles con cuotas de CPU o estado SIMD aislado.

Se reutiliza `--target x86_64-unknown-none`: el código usuario usa ABI SystemV, sin libc/redzone/SIMD/PIC, con direcciones menores de2GiB compatibles con el actual modelo de código. Un linker propio crea ELF64 ET_EXEC separado; build lo inspecciona y lo incorpora como bytes de rodata del kernel. No se añaden módulos, structs, arrays o globals al lenguaje: estado y BSS se reservan con símbolos ASM, como en hitos anteriores.

ELF admitido: little-endian x86_64, hasta128KiB de archivo y8programheaders; LOADs legibles, alineados4KiB, sin solapamiento de páginas, `filesz<=memsz`, memoria en[0x40000000,0x40100000), entry dentro de bytes ejecutables. Se rechazan tipos de segmento distintos de LOAD/NULL/GNU_STACK no ejecutable. Todo se valida antes de asignar; páginas PMM se borran, reciben datos y se publican con U y W^X. BSS y stack se ponen a cero. Fallos de asignación deshacen las hojas y liberan sus páginas después de invalidar TLB. El loader no usa ni interpreta sectionheaders/relocaciones; el inspector del build comprueba que el artefacto producido carece de REL/RELA y símbolos indefinidos.

PML4[0] pasa a U pero PDPT[0] y todas las hojas de identidad siguen supervisor. PDPT[1] conecta un PD/PT BSS reservado; no se expone el alias físico kernel al usuario. Stack usuario16KiB en[0x401fc000,0x40200000), guard no presente0x401fb000, resto de huecos ausentes. TextRX, rodataR-NX y datos/stackRW-NX. Al salir/fallar se vuelve al controlador con IF0, se retiran las hojas y se libera PMM antes de otra invocación.

GDT conserva kernel8/16 y añade SSusuario0x1b, CSusuario0x23 y TSS64 en0x28. RSP0 usa stack supervisor dedicado32KiB; iomap_base104 excede límite103 y niega puertos. IRETQ fija RFLAGS0x202 y limpia GPR ajenos a RDI. Entrada usuarioRSP8mod16; `_user_start` lo alinea antes de llamar Zen. Salida abandona el stack del trap y recupera seis callee-saved/RSP del controlador. TSS/GDT/controlador son supervisor.

Se elige `int0x80` para compartir la entrada IDT que ya preserva15GPR; solo esta puerta tiene DPL3. Se pospone la instrucción SYSCALL/SYSRET y sus MSR/GS/validación de retorno, sin afirmar que esté implementada. RAX=número/resultado; RDI,RSI,RDX=argumentos. write1,exit2,ticks3; errores en complemento a dos: EFAULT−14,EINVAL−22,ENOSYS−38. write admite como máximo4096bytes y valida todas las hojas del rango antes de emitir un byte. Los manejadores permanecen IF0; el PIT se rearma durante usuario y cuenta IRQs, sin cambiar de proceso.

GP/PF y otras excepciones síncronas explícitas terminan la invocación con128+vector; no se reescribe su RIP. NMI/doublefault/machinecheck/IRQs inesperadas siguen fatales, al igual que PF con RSVD o sin bitU y cualquier excepción originada en el kernel de una syscall. El marco completo debe residir en el stack RSP0 y tener CS/SS exactos de usuario. El fallo de usuario no puede autorizar un acceso kernel.

## Evidencia y límites

Caso0 comprueba CPL3/IOPL0/IF1,14GPR de retorno, BSS cero, write Zen, seis rechazos, ENOSYS y avance real del PIT. Se recargan seis invocaciones que intentan leer kernel, escribir text, CLI, ejecutar stack, leer guard y usar int0x81. El controlador comprueba vector/error/CR2 apropiados y recuperación de PMM tras cada una; no se acepta el éxito de una sonda que retorna normalmente.

No hay FS, shell, IPC, procesos concurrentes, fork/exec, TLS, señalización, ASLR, KPTI, cuotas de CPU ni contexto FPU/SIMD. Tampoco IST/doublefault robusto ni guard en el stack RSP0. Volatile no aporta garantías SMP. Un programa infinito requiere timeout externo QEMU. El siguiente hito añade VFS/RAMFS e init/shell con alcance verificable.

## Agentes

Se reutilizan agentes Sol para trabajo acotado y revisión cruzada. Se solicitaron perfiles Sol/high y Sol/medium al crear nuevos agentes, pero la herramienta rechazó el alta por límite de chats; `followup_task` no permite cambiar modelo/esfuerzo de agentes existentes. Por tanto se documenta la reutilización y no se afirma un rerouting que no ocurrió. boot_engineer confirmó modelo Sol; context_recovery conserva su selección Sol de Hito5. Tras la instrucción explícita del usuario de no usar Astra se detuvo la revisión de identidad no verificable y se repartió entre esos dos agentes, cada uno revisando código ajeno. Sin datos medidos de tokens/coste, no se cuantifica ahorro.
